# GirlfriendChatbot — RAG Knowledge Base Spec

> Give this file to the RAG agent. It builds the mood-detection knowledge base
> that the backend's `retrieve()` injects into Azure OpenAI prompts.
> No vector DB. File-based JSON index, works offline at runtime.

## 0. Goal and contract

- Backend imports `retrieve(query: string, topK?: number): Promise<Snippet[]>`
  from `src/lib/rag.ts`. This spec defines exactly how that function works
  and what data it searches.
- Closed mood set (must match backend, do not extend):
  `happy | sad | angry | anxious | tired | lonely | neutral`

## 1. Files to create (under `girlfriendchatbot/`)

```
src/lib/mood-kb/moods.md       # 6 moods + neutral (§2)
src/lib/mood-kb/questions.md   # 40 probing questions, tiered (§3)
src/lib/mood-kb/playbooks.md   # per-mood reply guidance + crisis (§4)
scripts/build-kb.mjs           # embeds via Azure, writes index (§5)
src/lib/mood-kb/index.json     # GENERATED by script, do not hand-edit
src/lib/rag.ts                 # retrieve() implementation (§6)
```

## 2. `moods.md` — content requirements

- Exactly 7 `## ` sections in this order:
  `## happy`, `## sad`, `## angry`, `## anxious`, `## tired`,
  `## lonely`, `## neutral`.
- Each section has three sub-parts, each under 150 words total per section:
  1. `Signals:` — 4–6 bullets (observable text cues, e.g. tired:
     "short replies, mentions of exhaustion, 'drained', 'long day'").
  2. `Example phrases:` — 5 quoted user phrases per mood.
  3. `Don't mistake for:` — 1 line naming the closest confusable mood.
- Example skeleton:

```markdown
## tired
Signals:
- short replies, low energy words
- mentions of exhaustion, sleep, long day
...
Example phrases:
- "i'm drained, today was endless"
...
Don't mistake for: sad (tired wants rest, sad wants comfort)
```

## 3. `questions.md` — 40 probing questions, tiered

- Exactly three `### ` groups with these counts:
  - `### light (1-12)` — 12 casual openers. E.g. "How did today treat you?",
    "What was the best small moment today?"
  - `### deep (13-28)` — 16 follow-ups. E.g. "What's been sitting on your
    mind since evening?", "What do you wish had gone differently today?"
  - `### playful (29-40)` — 12 warm/playful probes. E.g. "If tonight had a
    weather, what would it be?", "Describe your mood as a song playing
    softly — which one?"
- Rules: indirect mood probes only. Never "What is your mood?" Never clinical
  wording. One question per line, numbered, `- ` bullet or `1. ` list.
- The backend probe planner draws from these; keep them girlfriend-voiced,
  caring + playful, SFW.

## 4. `playbooks.md` — per-mood reply guidance + crisis

- Exactly 8 `## ` sections: one per mood (same 7 as `moods.md`) plus
  `## crisis` last.
- Each mood section has exactly:
  1. `Tone:` — 3 adjectives (e.g. tired: "soft, unhurried, tender").
  2. `Length:` — sentence range (e.g. `2-3 sentences`).
  3. `Openers:` — 2 template first lines (with `...` slot for personalizing).
  4. `Follow-up:` — 1 question template.
  5. `Avoid:` — 2 things never to say for that mood.
- `## crisis` section (verbatim behavior for self-harm disclosures):
  - Validate ("I'm really glad you told me"), encourage contacting a trusted
    person / local helpline / emergency number immediately, offer to listen.
  - No diagnosis, no moralizing, no mention of policies or AI identity.
  - Keep under 5 sentences.

## 5. Index build (`scripts/build-kb.mjs`)

- Chunking: split each `.md` file by `## ` (for `moods.md`, `playbooks.md`)
  and by `### ` groups then lines (for `questions.md`, batch 4 questions per
  chunk). Chunk shape: `{ id: "<file>#<heading>[/<n>]", text }`.
- Cap each chunk at 800 chars; if longer, split on sentence boundaries
  (`. `, `? `, `! `).
- Expected total: 25–60 chunks. Fail the script with non-zero exit if outside
  that range (catches truncated KB files).
- Embedding: `AzureOpenAI` with `AZURE_OPENAI_EMBED_DEPLOYMENT`, batch 10
  texts per `embeddings.create()` call. Read endpoint/key/api-version from
  the same env names as the backend spec.
- Output `src/lib/mood-kb/index.json`:

```json
{
  "model": "<embed deployment name>",
  "dim": 1536,
  "builtAt": "<ISO timestamp>",
  "chunks": [{ "id": "moods.md#tired", "text": "...", "embedding": [0.01, ...] }]
}
```

- Add to `package.json`: `"kb:build": "node scripts/build-kb.mjs"`.
- Document: re-run `npm run kb:build` after any KB edit or embed-model change.
- Commit `index.json` (small, <2MB). Never commit `.env`.

## 6. `src/lib/rag.ts` — exact API the backend expects

```ts
export type Snippet = { id: string; text: string; score: number };

export async function retrieve(
  query: string,
  topK = 4,
): Promise<Snippet[]>;

export async function loadIndex(): Promise<{
  chunks: { id: string; text: string; embedding: number[] }[];
}>;
```

- Implementation:
  1. Lazily load + cache `src/lib/mood-kb/index.json` via `fs/promises`
     + `path.join(process.cwd(), "src/lib/mood-kb/index.json")`.
     (Use `process.cwd()`, not `__dirname`, so it works in Next.js routes.)
  2. Embed `query.slice(0, 1000)` with the same embed deployment.
  3. Cosine similarity over all chunks, sort desc, return top `topK`.
  4. On ANY error (missing file, Azure failure): `console.error` and return
     `[]` — the backend must still answer without KB context.
- No dependencies beyond `openai` + `fs`/`path`.
- No `NEXT_PUBLIC_` env usage. No client-side imports.

## 8. Acceptance

- [ ] 3 md files exist with the exact headings/counts above; chunk count 25–60.
- [ ] `npm run kb:build` succeeds and writes valid `index.json` with `dim` > 0.
- [ ] `retrieve("i feel exhausted and drained", 2)` returns tired-related chunk ids.
- [ ] `retrieve("work is driving me crazy today", 2)` returns angry/anxious chunks.
- [ ] No secrets in md/json files. `npm run typecheck` passes.
- [ ] Backend contract holds: `retrieve()` returns `{ id, text, score }[]`,
  empty array on failure, never throws to the caller.
